# v6.1 staged migration workspace

This directory is generated by `scripts/migrate-city-cost-v6-1.mjs` for the owner-approved migration of the
121-city library. It is staging only: the live `data/reference/city_costs_app_aud.csv` is read to freeze its
hash and is never written here.

The frozen protocol records the input CSV and FX hashes, source window, prompt hashes, implementation hashes,
three-call/search limits and the 121-city identity frame. Raw and telemetry files are retained per city/source;
the checkpoint and call-provenance ledgers make interruption/resume and call-level reuse auditable. Normalized
and materialized artifacts are generated by the shipped v6.1 parser/materializer and persistence adapter.

Commands:

```text
node scripts/migrate-city-cost-v6-1.mjs init
node scripts/migrate-city-cost-v6-1.mjs status
node scripts/migrate-city-cost-v6-1.mjs reuse --source-experiment-dir <experiment-014-path> [--cities ...]
node scripts/migrate-city-cost-v6-1.mjs assign --city <city> --assignment-id <id> --agent-id <id> --sources expedia_3star,budgetyourtrip_daily_tiers,numbeo_drinks
node scripts/migrate-city-cost-v6-1.mjs materialize [--cities ...]
node scripts/migrate-city-cost-v6-1.mjs check
node scripts/import-city-cost-v6-1-provenance.mjs --check
node scripts/rehearse-city-cost-v6-1-cutover.mjs --check
```

`materialize` refuses a city with a pending source slot. `check` and assignment `--check` are read-only. The
provenance importer refuses partial sidecars and the live database; a non-live database path is required for a
test import. It resolves frozen city IDs with canonical country aliases, rejects ambiguous identity matches and
duplicate migration keys, and reuses matching estimates on replay. The rehearsal copies the local database to a
temporary path, proves insert/replay/rollback and API provenance round-trip, and checks that the live CSV is unchanged.
No Phase 11 cutover is implied by any artifact in this directory.
