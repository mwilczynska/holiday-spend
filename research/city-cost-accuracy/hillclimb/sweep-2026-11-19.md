Owner request: can city costs be generated with any model and effort, and how accurate are other Claude
settings? Lanes 110 to 118 copy Luna's frozen 102 tasks (v1.2 food/drink-search prompt) for 20 dev cities chosen by
hash (`make-lane.mjs --sample 20 --seed sweep-2026-11-19`). Each worker: `claude -p` on the owner's subscription,
the exact Luna worker message, app system prompt, WebSearch only, no user or project instructions. Lane 113 (Haiku
max) reuses lane 108 answers and has only the 5 sample cities 108 reached. Report: `sweep-report.mjs`
(`sweep-2026-11-19.json`). Not assessed under the acceptance rule: 20 cities are a screen, not a test.

the production table unchanged (fitted on Luna, these cities included, so Luna's own figure is in-sample).

With each model's own per-anchor correction fitted leave-one-city-out on the 20 cities: Luna 0.176, Sonnet xhigh
0.176, Opus medium 0.179, Sonnet low 0.186, Sonnet high 0.187, Haiku medium 0.209, Haiku high 0.212, Haiku low 0.214,
Haiku xhigh 0.253 (Luna better by 0.076, CI 0.025 to 0.134).

Findings: every setting completes; only Haiku max exceeds one request's output ceiling. Sonnet and Opus are closer to
the references than Luna before correction, and Luna's table overshoots them (3-star factor 0.62), so model-specific
tables are needed before those models can match Luna in the app. Haiku does not improve with effort above high.
The CLI usage field `webSearchRequests` does not match the model's search calls; searches are counted from WebSearch
tool calls.
